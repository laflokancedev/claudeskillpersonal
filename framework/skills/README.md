# skills/

**Source de vérité de l'expertise.** Un dossier = un domaine = un `SKILL.md`. Les skills
sont chargés par l'agent `specialist` ; ils n'ont aucune dépendance sortante (feuilles
réutilisables) et **ne doivent jamais empiéter** sur le domaine d'un autre skill.

Domaines : `architecture`, `ui-ux`, `frontend`, `backend`, `api`, `database`,
`security`, `performance`, `devops`, `testing`, `ai`, `documentation`, `review`.

Chaque `SKILL.md` respecte 8 sections : OBJECTIF · RESPONSABILITÉS · INTERDITS · FORMAT
DE SORTIE (terminé par `## Hand-off`) · CHECKLIST · CRITÈRES DE QUALITÉ · EXEMPLES ·
BONNES PRATIQUES.

Ajouter un skill sans toucher aux autres : voir `docs/ADDING-A-SKILL.md`. Gabarit :
`templates/SKILL.template.md`.
